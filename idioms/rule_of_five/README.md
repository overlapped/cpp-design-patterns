# Rule of Five

Rule of Five — идиома C++11: если классу нужен хотя бы один из пяти
специальных членов (деструктор, копирующий/перемещающий конструктор,
копирующее/перемещающее присваивание), объявите или удалите все пять.
`Buffer` владеет сырым массивом `int*`, поэтому все пять нужны: иначе
компилятор сгенерирует поверхностное копирование и получится double free.

## Файлы

- `rule_of_five.hpp` — класс `Buffer` с сырым `int* data_` и всеми пятью
  специальными членами; копирующее присваивание реализовано через
  copy-and-swap, есть свободная функция `swap`.
- `test.cpp` — проверяет глубокое копирование, опустошение источника
  при move, безопасность self-assignment, перемещающее присваивание и
  хранение `Buffer` в `std::vector`.

## Ключевые идеи

1. **Деструктор освобождает ресурс.**
   `~Buffer() { delete[] data_; }` — единственное место, где массив
   освобождается. Все остальные специальные члены обязаны оставить
   объект в состоянии, при котором этот деструктор корректен
   (`data_ == nullptr` или валидный массив).

2. **Копирующий конструктор — глубокая копия.**
   `Buffer(const Buffer&)` выделяет `new int[other.size_]` и поэлементно
   копирует. Тест `CopyIsDeep` проверяет, что изменение копии не
   затрагивает оригинал.

3. **Перемещающий конструктор — «кража» ресурса, `noexcept`.**
   `Buffer(Buffer&&) noexcept` забирает `data_` и `size_`, а источнику
   выставляет `size_ = 0; data_ = nullptr`. `noexcept` важен: иначе
   `std::vector` при реаллокации будет копировать, а не перемещать.
   Тест `MoveEmptiesSource`.

4. **Копирующее присваивание — copy-and-swap.**
   `operator=(const Buffer&)` создаёт `Buffer tmp(other)` (может бросить —
   исходный объект не тронут), затем `swap(tmp)` (`noexcept`). Это даёт
   строгую гарантию исключений и корректно обрабатывает self-assignment
   благодаря проверке `this != &other`. Тест `CopyAssignmentIsSafe`,
   включая `b = b`.

5. **Перемещающее присваивание — `noexcept`, с проверкой self-assignment.**
   `operator=(Buffer&&) noexcept` освобождает текущий `data_`, забирает
   ресурс у `other` и обнуляет источник. Проверка `this != &other`
   защищает от `delete[] data_` у самого себя. Тест
   `MoveAssignmentEmptiesSource`.

6. **Свободная `swap` рядом с классом.**
   `inline void swap(Buffer&, Buffer&) noexcept` вызывает `a.swap(b)`.
   Это позволяет `std::swap` находить её через ADL и делает
   copy-and-swap переносимым.

## Ограничения

1. **Сырой `int*` — только для демонстрации.**
   В реальном коде используйте `std::vector<int>` или
   `std::unique_ptr<int[]>`: они уже реализуют Rule of Five корректно,
   и писать пять специальных членов вручную не нужно.

2. **Перемещающие операции должны быть `noexcept`.**
   Если сделать `Buffer(Buffer&&)` без `noexcept`, `std::vector` при
   реаллокации выберет копирование (потому что копирование может
   бросить, а перемещение — нет). Это не ошибка компиляции, а тихая
   деградация производительности.

3. **Copy-and-swap требует `swap`, который не бросает.**
   Если `swap` может бросить, строгая гарантия исключений в
   `operator=` теряется. Поэтому `swap` объявлен `noexcept` и меняет
   только `size_` и `data_`.
