# Virtual Constructor (clone)

Virtual Constructor — идиома C++: в языке нет виртуальных
конструкторов, но есть виртуальный метод `clone()`, который
возвращает копию объекта. Через базовый указатель можно копировать
полиморфные объекты, не зная их конкретного типа. Часто используется
вместе с паттерном Prototype.

## Файлы

- `virtual_constructor.hpp` — базовый `Shape` с чисто виртуальным
  `clone()` и два наследника: `Circle` и `Rectangle`. Свободная
  функция `cloneAll` копирует вектор `unique_ptr<Shape>`.
- `test.cpp` — проверяет, что `clone()` возвращает правильный тип,
  работает через базовый указатель, даёт независимую копию и
  сохраняет порядок в `cloneAll`.

## Ключевые идеи

1. **`clone()` — виртуальный «конструктор копирования».**
   `virtual std::unique_ptr<Shape> clone() const = 0` в базовом
   классе. Каждый наследник реализует его как
   `std::make_unique<Circle>(*this)` — то есть вызывает свой
   копирующий конструктор.

2. **Возврат `unique_ptr`, а не сырого указателя.**
   `clone()` возвращает `std::unique_ptr<Shape>` — владение явное,
   утечек нет. Клиент не должен вручную вызывать `delete`.

3. **`clone()` — `const`, потому что копирование не меняет оригинал.**
   Это позволяет вызывать `clone()` на `const Shape&` и на
   `const std::unique_ptr<Shape>&` — что и делает `cloneAll`.

4. **Копирование через базовый указатель.**
   `cloneAll` принимает `const std::vector<std::unique_ptr<Shape>>&`
   и вызывает `s->clone()` для каждого элемента. Конкретные типы
   (`Circle`, `Rectangle`) не упоминаются — работает динамическая
   диспетчеризация.

5. **Глубокая копия, а не поверхностная.**
   `clone()` вызывает копирующий конструктор наследника, который
   копирует все поля (например, `r_` у `Circle`). Тест
   `CloneIsIndependent` уничтожает оригинал и проверяет, что копия
   жива — это доказывает, что копия не разделяет данные с
   оригиналом.

## Ограничения

1. **Каждый наследник обязан реализовать `clone()`.**
   Если добавить новый класс, наследующий `Shape`, и забыть
   `clone()`, компилятор не соберёт код (чисто виртуальный метод).
   Это хорошо: ошибка ловится на этапе компиляции, а не в runtime.
   Но это и цена: каждый новый тип должен явно поддержать
   клонирование.

2. **`clone()` требует копируемости наследника.**
   `std::make_unique<Circle>(*this)` вызывает копирующий конструктор
   `Circle`. Если наследник move-only (например, содержит
   `std::unique_ptr`), `clone()` не скомпилируется. В этом случае
   нужен либо move-вариант (`cloneMove()`), либо отказ от
   клонирования.

3. **Не заменяет `std::variant` + `std::visit` для закрытых иерархий.**
   Если набор типов фиксирован и известен заранее, `std::variant`
   с `std::visit` может быть быстрее (нет виртуальных вызовов) и
   безопаснее (нет ручного `clone()`). Virtual Constructor уместен,
   когда иерархия открыта для расширения.
