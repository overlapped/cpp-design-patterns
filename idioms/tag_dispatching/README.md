# Tag Dispatching

Tag Dispatching — идиома выбора перегрузки на этапе компиляции через
пустой тип-тег. Вместо `if constexpr` или SFINAE вы передаёте тег
(например, `std::random_access_iterator_tag`) в перегрузку, и
компилятор выбирает нужную реализацию по типу тега. Это даёт
статическую диспетчеризацию без виртуальных вызовов и без ветвлений
в runtime.

## Файлы

- `tag_dispatching.hpp` — перегрузки `process` для
  `std::random_access_iterator_tag` (быстрый путь) и
  `std::forward_iterator_tag` (медленный путь); `dispatch` определяет
  категорию итератора через `std::iterator_traits` и вызывает
  нужную перегрузку.
- `test.cpp` — проверяет, что `std::vector` идёт по быстрому тегу,
  `std::list` — по медленному, и что `process` действительно меняет
  элементы.

## Ключевые идеи

1. **Тег — пустой тип, перегрузка — по типу тега.**
   `void process(Iter first, Iter last, std::random_access_iterator_tag)`
   и `void process(Iter first, Iter last, std::forward_iterator_tag)` —
   две перегрузки с одинаковым именем и разными тегами. Компилятор
   выбирает ту, чей тег точнее подходит.

2. **`std::iterator_traits<Iter>::iterator_category` — источник тега.**
   `dispatch` вызывает `process(first, last,
   typename std::iterator_traits<Iter>::iterator_category{})`.
   Для `std::vector<int>::iterator` это
   `std::random_access_iterator_tag`, для `std::list<int>::iterator` —
   `std::forward_iterator_tag` (или `bidirectional_iterator_tag`,
   который неявно преобразуется в `forward_iterator_tag` при
   перегрузке).

3. **Статическая диспетчеризация — без `if` и без виртуальных вызовов.**
   Решение, какую перегрузку вызвать, принимается компилятором.
   В runtime нет ни ветвления, ни косвенного вызова — только
   инлайнится нужная версия.

4. **Быстрый путь использует свойства категории.**
   Для `random_access_iterator_tag` `process` может прыгать на
   `first + n` или использовать `last - first` для размера. Для
   `forward_iterator_tag` — только инкремент `++it`. Это и есть
   смысл тега: разрешить оптимизацию, недоступную для более слабой
   категории.

5. **`process` меняет элементы — тест `ProcessModifiesElements`.**
   Перегрузки принимают итераторы по значению (это нормально:
   итератор — дешёвая копия), но разыменование даёт ссылку на элемент
   контейнера, поэтому изменения видны снаружи.

## Ограничения

1. **Тег должен быть известен на этапе компиляции.**
   Tag Dispatching работает только когда категория итератора — часть
   типа. Для `std::any_iterator` или type-erased итераторов это не
   сработает: там категория известна только в runtime, и нужен
   виртуальный вызов или `std::variant` + `std::visit`.

2. **Нужны перегрузки для всех категорий.**
   Если `dispatch` вызывает `process` с `forward_iterator_tag`, а
   перегрузки для `bidirectional_iterator_tag` нет — компилятор
   выберет `forward` (потому что `bidirectional` наследуется от
   `forward`). Но если перегрузки для `forward` тоже нет — ошибка
   компиляции. Обычно пишут базовую перегрузку для самой слабой
   категории, а остальные — как оптимизации.

3. **Не заменяет `if constexpr` для не-итераторных случаев.**
   Tag Dispatching идиоматичен именно для итераторов и похожих
   «категорий» (например, `std::float_round_style`). Для произвольных
   свойств типа в C++17+ чаще используют `if constexpr` или
   `concepts` — они читаются проще.
