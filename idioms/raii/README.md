# RAII (Resource Acquisition Is Initialization)

RAII — идиома C++, при которой ресурс захватывается в конструкторе объекта
и освобождается в его деструкторе. Время жизни ресурса привязывается к
времени жизни объекта на стеке, поэтому освобождение происходит
детерминированно — в том числе при выходе из функции по исключению.

## Файлы

- `raii.hpp` — две обёртки: `FileHandle` над `std::FILE*` и `LockGuard`
  над `std::mutex`. Обе — move-only, копирование запрещено.
- `test.cpp` — проверяет, что файл закрывается при выходе из scope,
  мьютекс освобождается при исключении, владение передаётся через move,
  а конструктор бросает исключение, если файл не открылся.

## Ключевые идеи

1. **Захват в конструкторе, освобождение в деструкторе.**
   `FileHandle(const char* path)` вызывает `std::fopen`; `~FileHandle()`
   вызывает `std::fclose`. `LockGuard(std::mutex&)` вызывает `lock()`;
   `~LockGuard()` вызывает `unlock()`.

2. **Move-only: копирование запрещено.**
   `FileHandle(const FileHandle&) = delete` и
   `operator=(const FileHandle&) = delete`. Владение передаётся только
   через move-конструктор и move-присваивание, которые обнуляют
   источник (`file_ = nullptr`, `mutex_ = nullptr`), чтобы деструктор
   не освободил ресурс дважды.

3. **Детерминированное освобождение при исключении.**
   Если между захватом и концом scope бросается исключение, деструктор
   всё равно вызывается — стек разматывается, `~FileHandle()` и
   `~LockGuard()` срабатывают. Тест `LockReleasedOnException` это
   проверяет.

4. **Ошибка захвата — исключение из конструктора.**
   Если `std::fopen` вернул `nullptr`, конструктор `FileHandle` бросает
   `std::runtime_error`. Объект не создаётся, деструктор не вызывается,
   ресурс не утекает. Тест `ThrowOnMissingFile`.

5. **Доступ к ресурсу — через `get()` / `operator*`.**
   `FileHandle::get()` возвращает `std::FILE*` для передачи в `fread`,
   `fwrite` и т.п. Это единственный способ добраться до сырого ресурса;
   владение остаётся у обёртки.

## Ограничения

1. **RAII требует деструктора, который не бросает.**
   `~FileHandle()` и `~LockGuard()` объявлены `noexcept` (по умолчанию
   для деструкторов). Если освобождение ресурса может бросить
   исключение, его нужно либо подавить (`try/catch` внутри деструктора),
   либо вынести в отдельный `close()`, который вызывается явно.

2. **Копирование ресурса надо запрещать или делать move-only.**
   Если разрешить копирование `FileHandle`, два объекта будут владеть
   одним `FILE*` и оба вызовут `fclose` — double free. Поэтому
   копирование удалено, а move обнуляет источник.

3. **Не заменяет `std::unique_ptr` / `std::lock_guard`.**
   В реальном коде используйте стандартные обёртки: `std::unique_ptr`
   с кастомным deleter для `FILE*`, `std::lock_guard` для мьютекса.
   Здесь RAII показан на «сырых» `FILE*` и `std::mutex`, чтобы было
   видно, что именно делает деструктор.
