# Non-Member, Non-Friend Interface

Non-Member, Non-Friend Interface - это шаблон проектирования, который позволяет реализовать методы класса без использования его членов. Этот шаблон особенно полезен в случаях, когда методы не должны иметь доступа к приватным полям класса, и когда их реализация должна быть отделена от класса.

## Файлы

- `non_member_non_friend.hpp`: Основной заголовочный файл, содержащий класс `Money` и реализацию методов через свободные функции.
- `test.cpp`: Файл с тестами для проверки работы методов через свободные функции.

## Ключевые идеи

1. **Свободные функции**: Методы реализуются через свободные функции, которые работают только через публичные методы класса.
   - Это позволяет менять внутреннее представление класса, не трогая его публичный интерфейс.

2. **Нет доступа к приватным полям**: Свободные функции не имеют доступа к приватным полям класса, что обеспечивает инкапсуляцию.
   - Это позволяет изолировать реализацию методов от их использования, обеспечивая инкапсуляцию.

3. **Легкость тестирования**: Свободные функции легко тестировать, так как они не зависят от внутреннего состояния класса.
   - Это позволяет использовать стандартные тестовые фреймворки для проверки работы методов.

4. **Упрощение кода**: Свободные функции могут быть реализованы в отдельных файлах, что упрощает управление кодом.
   - Это позволяет разделить логику класса на несколько файлов, что упрощает его поддержку и понимание.

5. **Корректное обработку self-assignment**: Свободные функции могут корректно обрабатывать случай, когда объект присваивается самому себе.
   - Это позволяет избежать ошибок при работе с self-assignment.

## Ограничения

1. **Сложность для новых разработчиков**: Для новых разработчиков может быть сложным понять, как работает Non-Member, Non-Friend Interface.
   - В таких случаях может быть полезно начать с простых примеров и постепенно переходить к сложным сценариям.

2. **Необходимость реализации свободных функций**: Для использования Non-Member, Non-Friend Interface необходимо реализовать свободные функции.
   - Это может быть дополнительной сложностью для разработчиков.

3. **Отсутствие доступа к приватным полям**: Свободные функции не имеют доступа к приватным полям класса, что ограничивает их использование.
   - В таких случаях может быть полезно использовать другие шаблоны проектирования.
