# Hidden Friends (Скрытые друзья)

## Суть идиомы
**Hidden Friend** — это свободная функция или перегруженный оператор (`operator==`, `operator+`, `operator<<`, `swap`), объявленный и **определённый непосредственно внутри тела класса** с ключевым словом `friend`.

Несмотря на то, что функция не является членом класса и принадлежит окружающему пространству имён (`namespace`), по правилам стандарта C++ она **невидима** для обычного поиска имён (unqualified / qualified lookup). Единственный способ её найти — **ADL (Argument-Dependent Lookup / поиск Кёнига)**, который срабатывает только тогда, когда хотя бы один из аргументов вызова имеет тип этого класса.

---

## Зачем это нужно

### 1. Ускорение компиляции и чистые сообщения об ошибках
В крупных проектах в одном пространстве имён могут находиться сотни перегрузок `operator==` или `operator<<`.
* Если операторы объявлены в `namespace` (как обычные свободные функции), при **каждой** ошибке компиляции в выражении `x == y` компилятор проверяет все сотни кандидатов и выводит гигантскую простыню вида `note: candidate function not viable...`.
* Если оператор сделан **Hidden Friend**, он даже не рассматривается компилятором, если среди аргументов нет вашего класса. В C++20 стандартная библиотека (`std::ranges`, `std::span`, `std::compare`) перевела большинство операторов именно на эту идиому.

### 2. Защита от нежелательных неявных преобразований
Если у класса `A` есть конструктор от `int`, а у класса `B` — конструктор от `int`, обычная свободная функция `operator==(A, B)` может неожиданно сработать для совершенно посторонних типов или вызвать неоднозначность перегрузки (ambiguity). Hidden Friend сужает область видимости функции строго до случаев прямого участия целевого типа.

### 3. Удобство написания шаблонных классов
Внутри шаблонного класса `template <typename T> class Box` написать hidden friend гораздо проще, чем выносить шаблонный `operator<<` наружу с предварительным объявлением (forward declaration).

---

## Ограничения
* Поскольку функция невидима для обычного поиска, на неё нельзя взять указатель через имя пространства имён (`&ns::operator+` не скомпилируется).
* Реализация функции должна находиться прямо внутри определения класса (inline), её нельзя вынести в `.cpp`-файл без дополнительного объявления в `namespace` (что лишит её статуса «скрытой»).

---

## Сравнение подходов

| Характеристика | Метод класса (`bool operator==`) | Обычная свободная функция | Hidden Friend |
| :--- | :--- | :--- | :--- |
| **Симметричность левого и правого операндов** | Нет (`5 + obj` не работает) | Да (`5 + obj` работает) | Да (`5 + obj` работает) |
| **Засоряет глобальный набор перегрузок** | Нет | **Да (замедляет сборку)** | **Нет (видна только по ADL)** |
| **Работает для `operator<<` (`ostream`)** | Нет (`ostream` слева) | Да | Да |
