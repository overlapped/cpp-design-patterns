# NVI (Non-Virtual Interface)

NVI - это шаблон проектирования, который позволяет изолировать реализацию методов от их использования, обеспечивая инкапсуляцию и упрощая тестирование.

## Файлы

- `nvi.hpp`: Основной заголовочный файл, содержащий класс `Shape` и его наследники `Circle` и `Rectangle`.
- `test.cpp`: Файл с тестами для проверки работы шаблона NVI.

## Ключевые идеи

1. **Публичный метод не виртуален — нельзя переопределить контракт в наследнике, только точку расширения**:
   - В `nvi.hpp` определен публичный метод `describe`, который вызывает приватный виртуальный метод `name`.
   - Приватный виртуальный метод `name` реализуется в наследниках, что позволяет переопределять только точку расширения.

2. **Публичный невиртуальный метод вызывает приватный виртуальный**:
   - В `nvi.hpp` метод `describe` вызывает приватный виртуальный метод `name`.
   - Это позволяет изолировать реализацию метода от его использования, обеспечивая инкапсуляцию.

3. **Шаблонный метод**:
   - В `nvi.hpp` метод `scaledArea` является шаблонным методом, который вызывает виртуальный метод `area` и добавляет проверку на отрицательный фактор.
   - Приватный виртуальный метод `area` реализуется в наследниках, что позволяет переопределять только точку расширения.

4. **Инкапсуляция**:
   - NVI позволяет скрывать реализацию от клиента, предоставляя только интерфейс.
   - Это упрощает использование и тестирование классов, так как клиент не может переопределить публичный метод.

## Ограничения

1. **Для простых иерархий NVI избыточен — достаточно обычного виртуального метода**:
   - NVI может быть избыточен для простых иерархий, где не требуется сложной инкапсуляции и тестирования.
   - В таких случаях использование обычного виртуального метода может быть более простым и эффективным.

2. **Ограниченность**:
   - NVI не подходит для сложных сценариев, требующих большого количества переопределений.
   - В таких случаях может быть полезно использовать другие шаблоны проектирования.

3. **Сложность для новых разработчиков**:
   - NVI может быть сложным для понимания для новых разработчиков, не знакомых с шаблоном.
   - В таких случаях может быть полезно начать с простых примеров и постепенно переходить к сложным сценариям.
