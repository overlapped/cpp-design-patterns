# Copy-and-Swap

Copy-and-Swap — идиома реализации `operator=` через копирование и
последующий `swap`. Даёт строгую гарантию исключений, корректно
обрабатывает self-assignment «бесплатно» и позволяет одним оператором
покрыть и copy-, и move-присваивание. Цена — лишняя копия в цепочке.

## Файлы

- `copy_and_swap.hpp` — класс `String` с сырым `char* data_` и
  `operator=(String other)`, реализованным через `swap(*this, other)`.
  `swap` — friend-функция, `noexcept`.
- `test.cpp` — проверяет copy-присваивание, self-assignment,
  move-присваивание и свободную `swap`.

## Ключевые идеи

1. **`operator=` принимает по значению.**
   `String& operator=(String other)` — параметр `other` создаётся
   копирующим конструктором для lvalue и перемещающим для rvalue.
   Один оператор покрывает оба случая, отдельный
   `operator=(String&&)` не нужен.

2. **`swap` — `noexcept` и меняет только два поля.**
   `friend void swap(String&, String&) noexcept` меняет `size_` и
   `data_` через `std::swap`. `noexcept` обязателен: если `swap`
   бросит, строгая гарантия теряется.

3. **Строгая гарантия исключений — без `try`.**
   Если копирование в `other` бросит, оператор не дойдёт до `swap`,
   и `*this` останется нетронутым. `try/catch` не нужен — гарантия
   достигается порядком операций: сначала копия, потом `swap`.

4. **Self-assignment корректен «бесплатно».**
   При `a = a` параметр `other` — независимая копия `a`. `swap(*this,
   other)` меняет местами `a` и копию, после чего `other` уничтожается
   со старыми данными `a`. Проверка `this != &other` не нужна.
   Тест `SelfAssignment`.

5. **Move-присваивание работает через тот же оператор.**
   При `b = std::move(a)` параметр `other` создаётся перемещающим
   конструктором (`a` опустошается), затем `swap` забирает данные.
   Тест `MoveAssignment`.

## Ограничения

1. **Лишняя копия для lvalue.**
   `operator=(String other)` всегда создаёт копию параметра. Для
   дешёвых типов это нормально; для дорогих иногда выгоднее написать
   отдельные `operator=(const T&)` и `operator=(T&&)`, чтобы избежать
   копии при lvalue-присваивании.

2. **`swap` должен быть `noexcept`.**
   Если `swap` может бросить, строгая гарантия исключений в
   `operator=` теряется. Поэтому `swap` объявлен `noexcept` и меняет
   только `size_` и `data_`.

3. **Нужен корректный `swap` для всех полей.**
   Если добавить в класс новое поле, его нужно добавить и в `swap`.
   Забытое поле — тихая ошибка: после присваивания часть состояния
   останется старой.
