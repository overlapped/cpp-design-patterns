# std::atomic_ref (C++20)

`std::atomic_ref<T>` — это атомарный «вид» на **неатомарную**
переменную. В отличие от `std::atomic<T>`, он не владеет переменной
и не меняет её тип: поле остаётся обычным `int`/`bool`, но в нужный
момент через `atomic_ref` можно делать атомарные операции. Полезно,
когда структура данных в основном используется неатомарно, но в
одном месте (например, в статистике) требует атомарности.

## Файлы

- `atomic_ref.hpp` — три примера: `Stats` (обычные `int`, атомарный
  инкремент через `atomic_ref`), `Worker` (обычный `bool`, атомарная
  запись/чтение с `release`/`acquire`), `Counter` (CAS через
  `compare_exchange_weak` на неатомарном поле).
- `test.cpp` — проверяет однопоточный и многопоточный инкремент,
  флаг `done`, CAS с лимитом и многопоточный CAS до лимита.

## Ключевые идеи

1. **`atomic_ref` не владеет переменной.**
   `std::atomic_ref<int> ref(s.hits)` — это лишь «вид» на `s.hits`.
   Само поле остаётся обычным `int` и в однопоточном коде читается
   без накладных расходов `atomic`.

2. **`memory_order_relaxed` для счётчика.**
   `ref.fetch_add(1, std::memory_order_relaxed)` — достаточно, потому
   что нужна только атомарность инкремента, без синхронизации с
   другими переменными.

3. **`release`/`acquire` для флага `done`.**
   Запись `result = 42` происходит **до**
   `store(true, std::memory_order_release)`. Чтение `isDone` с
   `acquire` гарантирует: если увидели `true`, то увидим и
   `result == 42`. Это классическая пара для публикации данных.

4. **CAS через `atomic_ref`.**
   `compare_exchange_weak(expected, expected + 1)` работает так же,
   как у `std::atomic`, но на неатомарной переменной. Это позволяет
   делать lock-free структуры, где поле объявлено обычным `int`.

5. **Многопоточный CAS до лимита.**
   Тест `CounterManyThreads` — 8 потоков пытаются инкрементировать
   до лимита 5000. CAS гарантирует, что итог ровно 5000, не больше
   и не меньше.

## Ограничения

1. **Требует выравнивания.**
   `atomic_ref<T>` требует, чтобы `T` был выровнен по `alignof(T)`.
   Для `int` это обычно 4 байта — стандартные поля в структурах
   выровнены, так что проблем нет. Но если поле упаковано
   (`#pragma pack`), `atomic_ref` может не работать.

2. **Не заменяет `std::atomic` для владения.**
   Если переменная должна быть атомарной **всегда**, используйте
   `std::atomic<T>`. `atomic_ref` — для случаев «в основном
   неатомарно, но иногда атомарно».

3. **C++20 only.**
   В C++11/17 аналога нет — придётся либо делать поле
   `std::atomic`, либо использовать мьютекс.
