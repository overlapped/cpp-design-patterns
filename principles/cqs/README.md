# CQS (Command-Query Separation)

CQS — принцип проектирования: методы делятся на две категории.
**Query** возвращает данные и **не меняет** состояние (помечен
`const`). **Command** меняет состояние и **не возвращает** данные
(`void`). Смешивание — источник неожиданных побочных эффектов:
`getSize()` не должен очищать контейнер, `pop()` не должен
возвращать значение и менять размер одновременно.

## Файлы

- `cqs.hpp` — `bad::Stack` с нарушениями CQS (`getSize()` мутирует,
  `pop()` возвращает значение) и `good::Stack` с соблюдением
  (`size()`, `top()`, `empty()` — `const`; `push()`, `pop()` —
  `void`).
- `test.cpp` — проверяет, что `bad::getSize()` мутирует,
  `good::size()` идемпотентен, `good::pop()` возвращает `void`,
  `pop()` на пустом бросает, `top()` на пустом даёт `nullopt`.

## Ключевые идеи

1. **Query — `const`, не меняет состояние.**
   `good::Stack::size()`, `top()`, `empty()` помечены `const`.
   Повторный вызов даёт тот же результат — это проверяет тест
   `GoodQueryDoesNotMutate`.

2. **Command — `void`, меняет состояние.**
   `good::Stack::push()` и `pop()` возвращают `void`. Нельзя
   случайно использовать результат `pop()` — его просто нет.

3. **Проверка «можно ли» — отдельный query.**
   Вместо `pop()` с возвратом значения (который нельзя вызвать
   «просто так») — `empty()` как query, а `pop()` как command.
   Клиент сначала проверяет `empty()`, потом вызывает `pop()`.

4. **`top()` возвращает `std::optional<int>`.**
   Query, который может «не иметь значения», возвращает
   `nullopt`, а не исключение и не «магическое» -1. Это явно и
   безопасно.

5. **`pop()` на пустом стеке бросает исключение.**
   Command, который не может выполниться, сообщает об ошибке
   исключением. Это не нарушение CQS: `pop()` по-прежнему
   возвращает `void`.

## Ограничения

1. **CQS — правило по умолчанию, а не догма.**
   В реальном коде иногда нужно нарушить его: `std::map::erase(key)`
   возвращает количество удалённых элементов — это нарушение CQS,
   но полезное (клиент хочет знать, был ли элемент). Если command
   **естественно** возвращает результат, это допустимое исключение.

2. **Не все query обязаны быть `const`.**
   Ленивые вычисления (memoization) могут менять внутренний кэш
   в query. Формально это нарушение CQS, но на практике
   `mutable`-кэш в `const`-методе — распространённый приём.

3. **CQS не заменяет инкапсуляцию.**
   Даже если `size()` — `const`, это не значит, что класс
   правильно инкапсулирован. CQS — про разделение команд и
   запросов, а не про сокрытие данных.
