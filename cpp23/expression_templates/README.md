# Expression Templates

Expression Templates — идиома C++ для ленивых вычислений над
векторами. Вместо того чтобы вычислять `v1 + v2 + v3` по шагам
(создавая временные векторы), мы строим дерево выражений, которое
вычисляется один раз при присваивании. Экономия: нет временных
векторов, одно выделение памяти, один проход по данным.

## Файлы

- `expression_templates.hpp` — `Expr<Derived>` (CRTP-база),
  `Vec` (лист), `BinaryExpr<L, R, Op>` (узел), операции
  `AddOp`/`SubOp`/`MulOp`, перегрузки `operator+`/`-`/`*`,
  `assign()` и `operator+=` для вычисления выражения.
- `test.cpp` — проверяет сложение двух векторов, цепочку из трёх
  без временных, приоритет `*` над `+`, вычитание, `+=` с
  выражением и несовпадение размеров.

## Ключевые идеи

1. **`Expr<Derived>` — CRTP-база для всех выражений.**
   `self()` возвращает `const Derived&`. Перегрузки `operator+`
   принимают `const Expr<L>&`, а не конкретный тип — это
   позволяет строить дерево любой глубины.

2. **`BinaryExpr<L, R, Op>` хранит ссылки, а не значения.**
   `a + b + c` строит
   `BinaryExpr<BinaryExpr<Vec, Vec, AddOp>, Vec, AddOp>`.
   Временные объекты не создаются: все ссылки живы, пока живо
   выражение.

3. **Вычисление — только в `assign()` и `operator+=`.**
   `assign(result, expr)` проходит по данным один раз:
   `result[i] = expr[i]`. Одно выделение памяти (под `result`),
   один цикл — временных векторов нет.

4. **Приоритет операций сохраняется.**
   `a + b * c` строит `BinaryExpr<Vec, BinaryExpr<Vec, Vec,
   MulOp>, AddOp>`, потому что `operator*` имеет более высокий
   приоритет в C++. Результат — `a + (b * c)`, как и ожидается.

5. **`operator+=` с выражением — второй способ вычисления.**
   Не перезаписать, а добавить: `acc += a + b`. Полезно для
   аккумуляторов и накопления сумм.

## Ограничения

1. **Ссылки в `BinaryExpr` должны жить, пока живо выражение.**
   `auto e = a + makeVec({1,2,3});` — `makeVec` вернёт временный
   `Vec`, который умрёт в конце выражения, и `e` будет держать
   висячую ссылку. В реальном коде это ловится санитайзерами или
   решается через `std::reference_wrapper` с проверкой времени
   жизни.

2. **Размеры не проверяются в release.**
   `assert` отключён в `NDEBUG`, и несовпадение размеров даст UB.
   В продакшн-коде нужна проверка в `assign` (например,
   `if (expr.size() != v.size()) throw std::invalid_argument`).

3. **C++23 не обязателен.**
   Expression Templates работают и в C++11. Но в `cpp23/` они
   смотрятся логично рядом с `generator`, потому что оба про
   ленивые вычисления.
