# Read-Write Lock (Блокировка чтения-записи)

## Назначение
Паттерн **Read-Write Lock** разделяет доступ к разделяемому ресурсу на два режима:
* **Разделяемый (Shared / Read)**: неограниченное число потоков-читателей могут одновременно читать данные, не блокируя друг друга.
* **Эксклюзивный (Unique / Write)**: поток-писатель получает монопольный доступ — ни один читатель или другой писатель не может войти в критическую секцию, пока запись не завершится.

## Когда использовать
* При выраженном перекосе в сторону чтения (например, 90% операций чтения и 10% записи: кэши в памяти, таблицы маршрутизации, конфигурации, справочники).
* Когда само чтение занимает нетривиальное время (например, поиск по большому контейнеру, копирование или сериализация объекта), из-за чего обычный `std::mutex` становится узким местом.

## Когда НЕ использовать
* Если критическая секция очень короткая (пара инструкций — например, чтение/запись одного `int`): накладные расходы `std::shared_mutex` (атомарные счетчики читателей, системные вызовы) выше, чем у обычного `std::mutex` или `std::atomic`.
* При частой записи: возможен эффект голодания писателей или читателей (writer/reader starvation) в зависимости от реализации `std::shared_mutex` в стандартной библиотеке ОС.

## Ключевые детали реализации
* **`std::shared_lock` vs `std::unique_lock`**: В C++17 для `std::shared_mutex` используются два стандартных RAII-обертки: `std::shared_lock` для `const`-методов чтения (`get`, `contains`, `size`) и `std::unique_lock` для мутирующих методов (`set`, `erase`, `clear`).
* **Безопасный паттерн `get_or_compute` (Read -> Upgrade -> Double-Check)**: В C++ стандартный `std::shared_mutex` не поддерживает атомарное повышение блокировки (lock upgrade) с `shared` до `unique`, так как два читателя, одновременно решивших повысить блокировку, вызвали бы deadlock. Поэтому `shared_lock` сначала отпускается, берется `unique_lock`, и выполняется повторная проверка наличия ключа перед вычислением.
* **Отсутствие висячих ссылок**: Метод `get()` возвращает копию значения через `std::optional<Value>`, а не `const Value&`. Возврат ссылки наружу привел бы к гонке данных (data race), так как `shared_lock` освобождается при выходе из метода. Если копирование дорогое — используется `read_with()`, выполняющий коллбэк прямо под защитой `shared_lock`.

## Сравнение примитивов синхронизации

| Примитив | Читатели | Писатели | Накладные расходы |
| :--- | :--- | :--- | :--- |
| `std::mutex` | По одному | По одному | Низкие |
| `std::shared_mutex` | Параллельно | По одному (эксклюзивно) | Средние |
| `std::atomic<T>` | Lock-free | Lock-free | Минимальные (только тривиальные типы) |
