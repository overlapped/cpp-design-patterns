# Monitor Object (Объект-монитор)

## Назначение
Паттерн **Monitor Object** синхронизирует конкурентный доступ к объекту, гарантируя, что в каждый момент времени внутри его критических секций выполняется только один поток. Объект сам инкапсулирует мьютекс (`std::mutex`) и условные переменные (`std::condition_variable`), скрывая логику синхронизации от вызывающего кода.

## Когда использовать
* Когда несколько потоков одновременно читают и изменяют состояние общего объекта (например, очередь задач, пул соединений, кэш).
* Когда потокам нужно не просто захватывать блокировку, но и координировать работу по условиям («ждать, пока появятся данные» или «ждать, пока освободится место»).

## Ключевые детали реализации
* **Синхронизированные методы**: Каждый публичный метод захватывает `mutex_` при входе (через `std::lock_guard` или `std::unique_lock`) и автоматически освобождает его при выходе (RAII), включая выход по исключению.
* **Две условные переменные (`not_empty_` и `not_full_`)**: Разделение условных переменных позволяет пробуждать именно тот тип потоков, который может продолжить работу (потребителя после `push` и производителя после `pop`), избегая лишних пробуждений (thundering herd).
* **Корректная остановка (`close()`)**: Вызов `close()` устанавливает флаг `closed_ = true` и вызывает `notify_all()` для обеих условных переменных, чтобы ни один поток не завис в вечном ожидании при завершении программы. При этом потребители могут дочитать оставшиеся в очереди элементы до получения `std::nullopt`.
* **Отсутствие утечки блокировок**: Внутренний мьютекс не отдаётся наружу, а методы возвращают значения по значению (`std::optional<T>`), а не по ссылке на внутренние элементы контейнера.

## Сравнение с Active Object и Thread Pool

| Характеристика | Monitor Object | Active Object |
| :--- | :--- | :--- |
| **Модель выполнения** | Пассивная: код выполняется в потоке вызывающего | Активная: у объекта есть собственный рабочий поток |
| **Синхронизация** | Синхронная (поток блокируется на мьютексе/CV) | Асинхронная (вызов сразу возвращает `std::future`) |
| **Накладные расходы** | Минимальные (нет выделения памяти под задачи/очередь вызовов) | Выше (упаковка вызовов в `std::function` / `packaged_task`) |

## Примечания по потокобезопасности
* В данном примере `mutex_` объявлен как `mutable`, чтобы `const`-методы (`size()`, `empty()`, `is_closed()`) могли безопасно захватывать блокировку.
* Метод `capacity()` не требует блокировки, так как `capacity_` — константа, инициализируемая в конструкторе.
