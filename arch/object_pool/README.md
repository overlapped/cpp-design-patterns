# Object Pool

Object Pool — архитектурный паттерн: пул готовых к использованию
объектов. Клиент берёт объект из пула (`acquire`), использует и
возвращает (`release`). В отличие от Memory Pool (пул сырой памяти),
здесь хранятся сконструированные объекты, готовые к работе.
Классический пример — пул соединений с БД: создавать соединение
дорого, поэтому их создают заранее и переиспользуют.

## Файлы

- `object_pool.hpp` — шаблонный `ObjectPool<T>` с фабрикой
  `std::function<std::unique_ptr<T>()>`, методами `acquire()`,
  `release()`, `available()`.
- `test.cpp` — проверяет начальное заполнение, уменьшение
  `available()` при `acquire`, создание нового объекта при пустом
  пуле, возврат объекта в пул, переиспользование того же объекта и
  безопасность `release(nullptr)`.

## Ключевые идеи

1. **Пул хранит `std::unique_ptr<T>`.**
   `std::vector<std::unique_ptr<T>> free_` — владение явное,
   утечек нет. При уничтожении пула все свободные объекты
   уничтожаются автоматически.

2. **Фабрика создаёт новые объекты.**
   `Factory = std::function<std::unique_ptr<T>()>` — пул не знает,
   как создавать `T`. Клиент передаёт фабрику в конструкторе.
   Это делает пул универсальным: подходит для соединений, потоков,
   буферов, любых дорогих в создании объектов.

3. **`acquire()` возвращает `unique_ptr<T>`.**
   Если пул не пуст — берёт объект из `free_`. Если пуст — вызывает
   фабрику и создаёт новый. Клиент владеет объектом, пока не вернёт
   его через `release()`.

4. **`release()` принимает `unique_ptr<T>`.**
   Владение переходит обратно пулу: объект кладётся в `free_`.
   Если передан `nullptr`, ничего не происходит — `release(nullptr)`
   безопасен.

5. **Переиспользование вместо создания.**
   После `release` и повторного `acquire` возвращается **тот же
   объект** (значение сохранилось, фабрика не вызывалась). Тест
   `ReusesReleasedObject` проверяет это: `next` не увеличился,
   `value` сохранилось.

## Ограничения

1. **`available()` — единственный точный счётчик.**
   `total()` возвращает `free_.size() + inUse_`, но `inUse_` в этой
   версии не обновляется — для образовательного примера достаточно
   `available()`. Если нужен точный `total()`, сделайте RAII-хэндл
   `PooledObject<T>`, который автоматически возвращает объект в пул
   при уничтожении.

2. **Пул не потокобезопасен.**
   `acquire()` и `release()` не защищены мьютексом. Для
   многопоточного сценария нужен `std::mutex` вокруг `free_` или
   lock-free очередь. Это осознанное упрощение: в embedded-коде пул
   часто используется из одного потока.

3. **Объекты не сбрасываются при возврате.**
   `release()` просто кладёт объект обратно в `free_`. Если объект
   хранит состояние (например, `busy = true`), оно сохранится.
   В реальном коде нужен `reset()` перед возвратом — но это
   ответственность клиента или отдельного `PooledObject`-хэндла.
