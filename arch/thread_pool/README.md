# Thread Pool (Пул потоков)

## Назначение
Паттерн **Thread Pool** управляет фиксированным набором рабочих потоков (workers) и очередью задач. Вместо дорогостоящего создания и уничтожения системного потока (`std::thread`) под каждую короткую задачу, потоки создаются один раз при инициализации и переиспользуются для выполнения поступающих задач.

## Когда использовать
* При большом потоке коротких асинхронных задач (обработка сетевых запросов, параллельные вычисления, фоновый ввод-вывод).
* Когда необходимо ограничить максимальное количество одновременно работающих потоков, чтобы избежать деградации производительности из-за частого переключения контекста (context switching).

## Ключевые детали реализации
* **Возврат результата (`std::future`)**: Метод `submit()` принимает произвольный вызываемый объект (функцию, лямбду, функтор) с аргументами и возвращает `std::future<ReturnType>`. Исключения, выброшенные внутри задачи, автоматически пробрасываются вызывающему потоку при вызове `.get()`.
* **Упаковка задач (`std::packaged_task`)**: Поскольку `std::queue<std::function<void()>>` требует копируемые объекты (или стирает тип), `std::packaged_task` (который является move-only) оборачивается в `std::shared_ptr` и захватывается в лямбду.
* **Graceful Shutdown (Корректное завершение)**: В деструкторе выставляется флаг `stop_ = true`, пробуждаются все потоки через `cv_.notify_all()`, после чего выполняется `join()`. Потоки завершают работу только тогда, когда флаг установлен **и** очередь задач полностью опустошена (`stop_ && tasks_.empty()`).
* **Защита от спурических пробуждений**: Ожидание в `worker_loop()` использует `cv_.wait(lock, predicate)`, что защищает от ложных пробуждений (spurious wakeups).

## Сравнение с Active Object

| Характеристика | Active Object | Thread Pool |
| :--- | :--- | :--- |
| **Количество потоков** | Обычно 1 выделенный поток на объект | $N$ потоков (обычно по числу ядер CPU) |
| **Состояние** | Инкапсулирует разделяемое состояние внутри себя | Без состояния (stateless) — выполняет независимые задачи |
| **Порядок выполнения** | Строго последовательный (FIFO) | Недетерминированный (параллельный) |

## Примечания по потокобезопасности и санитайзерам
* Класс потокобезопасен для одновременного вызова `submit()` из нескольких потоков-продюсеров.
* Для проверки отсутствия гонок данных (data races) рекомендуется запускать тесты с **ThreadSanitizer** (`-fsanitize=thread`).
