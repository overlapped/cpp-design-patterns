# SPSC Ring Buffer (Lock-Free циклический буфер)

## Назначение
**SPSC (Single-Producer Single-Consumer) Ring Buffer** — это структура данных фиксированного размера для сверхбыстрой передачи сообщений между ровно **одним потоком-писателем** и **одним потоком-читателем** без использования мьютексов, условных переменных и системных вызовов ОС (lock-free и wait-free).

## Когда использовать
* В системах реального времени, аудио/видео обработке, HFT (высокочастотном трейдинге) и игровых движках, где блокировка потока на мьютексе недопустима из-за непредсказуемых задержек (latency spikes).
* В **embedded-разработке** для обмена данными между обработчиком прерывания (ISR — Producer) и основным циклом программы (Main Loop — Consumer).

## Ключевые детали реализации
* **Разделение владения индексами**:
  * Индекс записи `tail_` изменяет **только Producer** (поэтому читает его через `memory_order_relaxed`, а публикует через `memory_order_release`).
  * Индекс чтения `head_` изменяет **только Consumer** (читает через `relaxed`, публикует через `release`).
  * Ни один поток не выполняет дорогих атомарных операций Read-Modify-Write (`compare_exchange`, `fetch_add`) — используются только обычные атомарные `load` и `store`.
* **Устранение False Sharing (`alignas(64)`)**: Поля `head_`, `tail_` и `buffer_` выровнены по границе кэш-линии процессора (обычно 64 байта). Без этого запись в `tail_` на первом ядре CPU аннулировала бы кэш-линию с `head_` на втором ядре (cache line ping-pong), снижая пропускную способность в разы.
* **Быстрая арифметика по модулю (`Capacity = 2^N`)**: Размер буфера ограничен степенью двойки на этапе компиляции (`static_assert`). Вместо медленной инструкции целочисленного деления (`index % Capacity`) используется побитовое И (`index & (Capacity - 1)`).
* **Различение «Пусто» и «Полно»**: Один слот буфера всегда остаётся незанятым. Это позволяет отличить пустой буфер (`head == tail`) от заполненного (`(tail + 1) & mask == head`) без введения третьего атомарного счётчика `size_`.

## Ограничения
* Строго **1 писатель и 1 читатель**. При добавлении второго писателя или читателя возникнет гонка данных (для MPMC нужны CAS-циклы и счётчики поколений на каждый слот).
* Буфер не блокирует поток при заполнении или опустошении: вызывающий код сам решает, что делать при возврате `false` / `std::nullopt` (повторить попытку в spin-loop, вызвать `std::this_thread::yield()` или отбросить пакет).

## Сравнение с BoundedMonitorQueue

| Характеристика | `SpscRingBuffer` | `BoundedMonitorQueue` |
| :--- | :--- | :--- |
| **Топология потоков** | Строго 1 Producer, 1 Consumer | Любое число (MPMC) |
| **Механизм синхронизации** | `std::atomic` (`acquire`/`release`) | `std::mutex` + `std::condition_variable` |
| **Поведение при ожидании** | Неблокирующее (`try_push` / `try_pop`) | Усыпление потока планировщиком ОС |
| **Задержка (Latency)** | Наносекунды | Микросекунды (переключение контекста) |
