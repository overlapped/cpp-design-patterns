# Circuit Breaker

Circuit Breaker — архитектурный паттерн отказоустойчивости. Если
сервис начинает падать, «предохранитель» размыкается и запросы
временно не идут к нему — быстрый fail вместо таймаута. Через
`timeout` предохранитель переходит в `HalfOpen` и пробует один
запрос: если успешно — замыкается, если нет — снова размыкается.

## Файлы

- `circuit_breaker.hpp` — класс `CircuitBreaker` с тремя состояниями
  (`Closed`, `Open`, `HalfOpen`), шаблонным `call()`, счётчиком
  ошибок и `timeout`.
- `test.cpp` — проверяет начальное состояние, открытие после порога
  ошибок, отклонение запросов без вызова функции, восстановление
  через `HalfOpen` и повторное открытие при падении в `HalfOpen`.

## Ключевые идеи

1. **Три состояния.**
   `Closed` — всё работает, запросы проходят. `Open` — запросы
   сразу отклоняются (`std::runtime_error`). `HalfOpen` — пробный
   период: один запрос решает, восстанавливаться или снова
   размыкаться.

2. **`call()` — шаблонный и принимает любой callable.**
   `template<typename Fn> auto call(Fn&& fn)`. Если цепь разомкнута,
   исключение бросается **до** вызова `fn` — это и есть «быстрый
   fail». Тест `OpenRejectsWithoutCalling` проверяет, что `called`
   остаётся `false`.

3. **`onFailure()` увеличивает счётчик и размыкает цепь.**
   При достижении `failureThreshold_` состояние становится `Open`,
   запоминается `openedAt_ = Clock::now()`. В `HalfOpen` любое
   падение снова размыкает цепь.

4. **`onSuccess()` сбрасывает счётчик и замыкает цепь.**
   В `HalfOpen` успех означает восстановление: `state_ = Closed`,
   `failureCount_ = 0`.

5. **Timeout — время в `Open` до перехода в `HalfOpen`.**
   `if (Clock::now() - openedAt_ < timeout_)` — пока не истёк,
   запросы отклоняются. После истечения — `state_ = HalfOpen` и
   следующий вызов пытается выполниться.

## Ограничения

1. **`call()` не потокобезопасен.**
   `state_`, `failureCount_`, `openedAt_` не защищены мьютексом.
   Для многопоточного сценария нужен `std::mutex` вокруг всего
   `call()` или `std::atomic` для полей. Это осознанное упрощение:
   в примере предохранитель используется из одного потока.

2. **`timeout` — фиксированный.**
   После истечения таймаута предохранитель всегда переходит в
   `HalfOpen` и пробует **один** запрос. Если хотите экспоненциальный
   backoff или несколько пробных запросов — нужно расширять логику.

3. **Нет сброса через `reset()`.**
   В текущей версии нельзя вручную замкнуть цепь. В реальном коде
   часто нужен `reset()` для административного вмешательства
   (например, после ручного исправления сервиса).
